How to read this report

  • Presence is relative to the parent. If a.b occurs 50 times and a.b.c in all 50 of those, c reads 100%. Tick absolute presence to score against the total record count. Inside an array the denominator is the number of elements.
  • Every array element is walked, and all indices collapse to one [] node. Ticking a path inside an array pulls that field from every element into a single JSON-array column, so the row count never changes. Use row unit to explode one collection instead.
  • ID-keyed objects collapse past the map-keys threshold into {*}. A map's keys are data, so {*} is tickable, projects as an object keyed by the map key, and can be exploded.
  • Per-path handling lives in Path detail. Click any row: the right pane opens on that path with a Handling block carrying Keep whole — one column, Unpack into child paths and Pretty-print on export, each with what it does written beside it. Whatever you set reads back in the row as a green chip.
  • Embedded JSON can be repaired and unpacked. A path holding stringified JSON can be unpacked from that block: values are repaired by a deterministic verify-loop — a fix is only accepted when the result actually parses, and content is never altered to get there — and the discovered structure is grafted into the tree. Anything unfixable is listed as residue, each value labelled with why: cut off mid-structure, two roots concatenated, not JSON at all, or no reading that parses.
  • Redact strips previews, enums and value labels from the tree, Stats and Path detail, and from the structural exports. It deliberately does not blank the preview table or the exported data — it is a report-hygiene switch, not a screen-share switch.
  • A container can stay whole. Keep whole — one column makes the path itself the column, its value written as JSON. Unticking a sub-node repackages the object without that key rather than splitting it into separate columns.
